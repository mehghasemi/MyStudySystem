# M1-الف: ثبت کتاب و ذخیرهٔ مقاوم

مجوز: درخواست ادامهٔ مالک و تأیید تحویل مرحله‌ای؛ فقط M1-الف فعال است.

همان پردازش محلی و SQLite حفظ می‌شود. NoteSection مالک متن بدنه، خلاصه، برداشت شخصی و کاربرد است؛ Note فقط سربرگ دارد. Source کتاب مالک متن اصلی، نویسنده و ناشر است. ReadingProgress نشانگر صفحه/فصل و آخرین مطالعه را مستقل از گزیده و revision متن نگه می‌دارد. فعلاً هر یادداشت حداکثر یک ارجاع کتاب دارد؛ چندمنبعی M2 است.

ارتقای ضروری schema 2 به 3 در یک تراکنش داده‌های G0 را به ساختار فعال M1 منتقل می‌کند؛ بکاپ یا Restore ساخته نمی‌شود. شکست تراکنش نسخهٔ قدیمی را دست‌نخورده نگه می‌دارد؛ برگشت به برنامهٔ G0 پس از ارتقا پشتیبانی نمی‌شود.

تمام ذخیره‌های متن و نشانگر دارای operation_id و expected revision هستند؛ نتیجهٔ retry پیش از revision خوانده می‌شود. پیش‌نویس یادداشت به‌صورت مستقل و خودکار در DB نگه داشته می‌شود و در صفحهٔ ثبت قابل بازکردن است؛ جایگزین ذخیرهٔ نهایی نیست. پاسخ دیررس اجازهٔ جایگزینی متن جدیدتر ندارد. داده و API فقط محلی می‌مانند.

طراحی: رنگ‌های آبی/کاغذی و دو تم و Vazirmatn نسخهٔ G0 حفظ می‌شود؛ فرم کتاب در صفحهٔ مستقل، خواندن متن در نمای مطالعه، بخش‌های اختیاری زیر بدنه در details. اولویت صفحهٔ امروز، آخرین کتاب واقعاً بازشده است؛ هیچ آمار مطالعه از بازبودن صفحه ساخته نمی‌شود. پیام تعارض کنار همان فرم، با حفظ پیش‌نویس و امکان ذخیرهٔ مستقل است.

Skills: software-architecture-design برای مالکیت متن و تراکنش؛ ui-ux-accessibility برای حالات خطا و تمرکز؛ frontend-design برای ادامهٔ زبان بصری G0؛ testing-quality-assurance و webapp-testing برای قطع پاسخ، دو تب، ادامهٔ صفحه و بستهٔ واقعی. از Node Playwright موجود استفاده می‌شود؛ Python Playwright نصب نیست.
